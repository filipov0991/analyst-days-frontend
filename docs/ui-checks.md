Node.js 22.23.5 использовался из временной установки `/tmp/node-v22.23.5-darwin-arm64`: Node.js не был доступен в исходном PATH. Для обычного запуска нужен установленный Node.js 22 LTS или совместимый более новый LTS. Зависимости установлены, точные версии зафиксированы в package.json/package-lock.json.

Первый запуск Turbopack в ограниченной среде не смог открыть внутренний порт; повтор с разрешением запуска локальных процессов прошёл. Это ограничение среды, не ошибка приложения. В первом UI-прогоне уточнены неоднозначные тестовые селекторы. Проверка клавиатуры выявила и помогла исправить уход фокуса из диалога; также исправлено доступное название фильтра зала. Финальный прогон успешен.

## Автоматические UI-сценарии

Все следующие проверки используют **явный перехват API в Playwright**. В приложении нет mock-режима или fallback на фикстуры.

1. Единственный первоначальный GET программы в dev/Strict Mode; добавление двух докладов, отображение переданного API конфликта, общий счётчик, удаление с повторным GET, перезагрузка с тестовым сохранённым состоянием, пустой второй день.
2. Открытие подробностей, описание и bio, время UTC→МСК, Tab/Shift+Tab внутри диалога, Escape, возврат фокуса, фильтр зала, пустой результат, сброс, смена дня.
3. Ответ 502 с HTML вместо JSON: понятные сообщения, повтор загрузки и синхронизации, восстановление доступности действий.
4. Прерванный PUT и быстрый двойной клик: один запрос изменения, повторный GET, отсутствие ложного успеха.
5. Все три страницы при 360 px: без горизонтального скролла.
6. Все три страницы при 768 px: без горизонтального скролла.
7. Все три страницы при 1440 px: без горизонтального скролла.
8. Неопределённый PUT и провал следующего GET: изменения отключены до успешного повтора синхронизации.
9. Медленный ответ предыдущего дня после быстрого переключения: устаревшие данные не подменяют текущий список.
10. Подробности выбранного доклада содержат серверный список конфликтов; переход к конфликтующему докладу внутри диалога.

Скриншоты тестов создаются в `test-results/`, traces сохраняются при ошибках. Эти генерируемые файлы исключены из Git.

## Реальная интеграция — не завершена

До уточнения пользователя GET `/api/health`, `/api/conference`, `/api/talks` отдельного backend успешно ответили: наблюдались 20 докладов, два дня, три зала и согласованные поля. Позже backend перестал принимать соединения на 127.0.0.1:8000; пробный интеграционный тест не дошёл до выбора докладов. В браузере подтверждено понятное отображение этой ошибки.

`tests/integration.spec.ts` подготовлен для будущего запуска с `REAL_API=1`, но его успешное выполнение **не заявляется**. После уточнения пользователя реальные интеграционные запросы больше не выполнялись.

Для отдельного полного прогона остаются:

- Cookie/Set-Cookie и Origin через Next.js proxy на реальном backend.
- Реальное сохранение и восстановление выбора, перезапуск backend с той же БД.
- Изоляция анонимных сессий, срок жизни cookie и серверная идемпотентность.
- Реальный расчёт полных/частичных/вложенных конфликтов и отсутствие конфликта встык.
- Docker build/run и другие браузеры (Safari/Firefox).
- Пользовательская проверка гипотезы «три доклада и конфликт за две минуты».

Backend-репозиторий, его файлы и процессы не изменялись. Push, развёртывание и создание внешних аккаунтов не выполнялись.
